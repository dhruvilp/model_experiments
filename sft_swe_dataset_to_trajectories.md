The nvidia/Nemotron-SFT-SWE-v3 dataset is an open, commercial-use collection of agentic trajectories (multi-turn problem-solving logs) gathered across frameworks like OpenHands and SWE-agent. When paired with modern developer agents and execution harnesses like Claude Code, OpenCode, or DeepSeek Harness, this data serves as a powerful seed for advanced synthetic data generation (SDG). [1, 2] 
Because this dataset provides real real-world software engineering (SWE) problems alongside structural attempts, you can perform four main categories of synthetic data generation:
------------------------------
## 1. Multi-Domain On-Policy Distillation (MOPD)
Instead of just copying the dataset’s existing traces (off-policy), you use the dataset's problem descriptions as prompts for your target agent. [3] 

* 
* On-Policy Rollouts: Feed the SWE problem descriptions from the dataset into an agent harness (e.g., DeepSeek Harness running a model like Qwen-3.8). Let the agent generate its own environment-docked trajectory to solve the bug. [1] 
* A/B Trajectory Pairing: Match the dataset's reference trajectory against your agent's generated trajectory to create preference datasets (DPO/RLHF) showing "Good vs. Bad" tool-use patterns.
* 

## 2. Trajectory Augmentation & Mutation
You can use Claude Code or open-source equivalents to mutate the existing Nemotron-SFT-SWE-v3 logs to create variants for robust training. [4] 

* 
* Counterfactual Data Augmentation: Use an LLM to rewrite parts of the successful trajectories in the dataset to introduce a synthetic agent mistake (e.g., executing the wrong bash command or misreading a file). Then, generate synthetic "recovery steps" showing how an ideal agent fixes its own error. [4] 
* Agent Style Translation: Translate trajectories generated by one harness style into another (e.g., rewriting an OpenHands web-style trajectory into a dense terminal-style trajectory suitable for Claude Code). [2, 4] 
* 

## 3. Execution-Verified SFT Trajectories
The core value of SWE problems is that they can be tested via an execution sandbox.

* 
* Negative-to-Positive Bootstrapping: Take the problem instances where the baseline Nemotron models failed, and route them to ultra-strong agents (like Claude Code) to see if they can generate a successful trajectory. If the sandbox tests pass, you have synthesized a brand new, verified training sample.
* Self-Correction Cycles: Capture multi-turn loops where an agent writes a buggy patch, triggers a test failure in the harness, reads the stack trace, and corrects itself. This generates high-value synthetic data for teaching models how to debug.
* 

## 4. Problem Evolution & Expansion (Re-scaffolding)
You can use the problem seeds in the dataset to expand your dataset volume exponentially.

* 
* Concept-Driven Extrapolation: Extract the specific coding concepts (e.g., "resolving circular imports in Django" or "fixing boundary conditions in Numpy matrices") from the dataset. Use your agent to generate entirely new, synthetic codebases and corresponding mock issues based on those concept seeds.
* Dependency/Environment Shifting: Take an existing problem from the dataset and synthetically upgrade the environment (e.g., modifying the code to break under Python 3.12 syntax rules), forcing the agent harness to generate a trace fixing dependency-related bugs. [5] 
* 

------------------------------
## Comparison of Harness Capabilities for SDG

| Strategy / Capability | Claude Code | DeepSeek Harness / OpenCode |
|---|---|---|
| Primary Use Case | Generating gold-standard "Teacher" trajectories to distill down to smaller student models. | High-volume, low-cost parallel simulation ("on-policy rollouts"). |
| Context Handling | Excellent at deep reasoning over long diffs, producing highly elegant, human-like terminal edits. | Superior at automatically compacting massive multi-turn token traces across long execution loops. |
| Licensing Considerations | Commercial constraints on utilizing output data to train directly competing frontier models. | Fully permissible or open-weights friendly for bootstrapping custom open-source coding models. |
